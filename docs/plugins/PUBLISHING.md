# Правила публикации плагинов

Это правила публикации в Telegram-канале
[t.me/octo_plugins](https://t.me/octo_plugins). Они жёстче, чем технические
ограничения приложения: приложение защищает пользователя, а канал отвечает за
доверие к плагину и его автору.

Плагин, который нарушает правила, отклоняется или удаляется из канала без
предупреждения. Автор может быть заблокирован для будущих публикаций.

---

## 1. Обязательные требования

1. **Открытые исходники.** В `source` — ссылка на публичный репозиторий,
   который содержит ровно тот код, что и в пакете.
2. **Лицензия.** В манифесте — SPDX-идентификатор (`MIT`, `Apache-2.0`,
   `GPL-3.0-only` и т.п.), в пакете — файл `LICENSE` с текстом лицензии.
3. **Манифест по схеме.** `id`, `name`, `version`, `apiVersion`,
   `minAppVersion`, `description`, `author`, `main`, `license`.
4. **Только JavaScript и статические ресурсы.** Никаких `.node`, `.so`,
   `.dll`, `.exe`, `.wasm`, `.py`, `.sh`, `.html`, `.jar`.
5. **Подпись для статуса «проверен».** Издатель канала или доверенный
   ревьюер подписывает `id`, `version` и SHA-256. Без подписи плагин может
   быть в канале как «без подписи», но не получает бейдж проверенного.
6. **SemVer.** `1.2.3`, `1.2.3-beta.1`. Уже опубликованную версию нельзя
   перезаписывать другим содержимым.
7. **Changelog.** Для каждой версии — короткое описание изменений на русском
   или английском.
8. **Минимальные разрешения.** `permissions` и `networkHosts` должны
   соответствовать коду. При установке приложение показывает каждое
   запрошенное разрешение.
9. **Совместимость.** `minAppVersion` — реальная минимальная версия, на
   которой плагин проверен.
10. **Размер.** Пакет до 8 МБ, распакованный — до 24 МБ, до 200 файлов.

## 2. Запрещено

### Безопасность и приватность

- Читать, передавать или хранить cookies, токены, пароли, содержимое сессии,
  историю, переписки и другие данные пользователя.
- Использовать `document.cookie`, `localStorage`, `sessionStorage`,
  `indexedDB`, `caches` для обхода `octo.storage`.
- Скрывать сетевую активность: прямые `fetch`, `XMLHttpRequest`, `WebSocket`,
  `EventSource`, `sendBeacon`, динамические `<script>`/`<iframe>`.
- Выполнять `eval`, `new Function`, динамический `import()`, `importScripts`,
  `WebAssembly`, Worker-потоки.
- Загружать и исполнять код с сервера, кроме собственного статического
  JavaScript из пакета.
- Обращаться к `require`, `process`, `Buffer`, `__dirname`, `module.exports`,
  `ipcRenderer`, `shell`, `webFrame`, `desktopCapturer`.
- Пытаться обойти проверку разрешений, статический аудит, песочницу,
  подпись или проверку целостности.
- Использовать обфускацию, минификацию без исходников, большие base64-блоки,
  `\x`/`\u`-последовательности для сокрытия кода.
- Майнить криптовалюту, запускать скрытые вычисления, ботнеты, DDoS.
- Красть, подменять или перехватывать пользовательский ввод.
- Распространять вредоносное ПО, шпионские модули, стилеры, ransomware.

### Правила TikTok и закон

- Обходить технические защиты TikTok, подделывать подписи, токены и запросы.
- Парсить приватные API, массово скачивать контент, накручивать просмотры,
  лайки, подписчиков, комментарии.
- Автоматизировать спам, массовые рассылки, обход блокировок.
- Нарушать авторские права, публиковать чужой контент без прав.
- Собирать персональные данные без согласия и законного основания.

### Канал и доверие

- Имперсонировать TikTok, TikTok Octo, автора другого плагина или сотрудника.
- Использовать название и иконку, вводящие в заблуждение.
- Скрывать платную подписку, донат или внешний сервис за кнопкой установки.
- Встраивать рекламу, реферальные ссылки и партнёрские программы без явного
  указания в описании.
- Требовать отключить защиту, антивирус, прокси или проверку подписи.
- Публиковать плагин, который делает что-то иное, чем заявлено в описании.

## 3. Разрешения и сеть

| Разрешение    | Когда допустимо                                                         |
| :------------ | :---------------------------------------------------------------------- |
| `page:css`    | только для оформления; без внешних `url()` и `@import`                  |
| `page:script` | только если без DOM-кода функция невозможна; объясните зачем в описании |
| `network`     | только для собственного API; перечислите точные хосты                   |
| `navigation`  | только осмысленные переходы по tiktok.com; не спам и не накрутка        |
| `shortcuts`   | только для функций плагина; не перехватывайте системные клавиши         |
| `links`       | только для https-ссылок на сайт автора или документацию                 |
| `playback`    | только для управления воспроизведением или реакции на паузу/скорость    |
| `feed`        | только для осмысленной навигации по ленте по запросу пользователя       |
| `downloads`   | только для сохранения выбранного пользователем медиа с TikTok/CDN       |
| `overlay`     | только для коротких статусных плашек поверх страницы                    |
| `i18n`        | для подстройки строк плагина под выбранный язык приложения              |
| `clipboard`   | только для копирования результата по явному действию пользователя       |
| `os:notify`   | только для редких важных уведомлений о завершении фоновых задач         |

Для `network`:

- `networkHosts` — минимальный список, без `*` в корне;
- только `https://`, кроме `localhost` для разработки;
- никаких запросов к `tiktok.com`, его CDN и аналитике;
- никакой передачи cookies, заголовков сессии и содержимого страницы без
  явного согласия пользователя;
- понятная политика приватности, если собираются любые данные;
- сервер должен быть стабильным и иметь контакт для безопасности.

Для скриншотов в постах канала:

- максимум 4 изображения, только https-ссылки или файлы из пакета;
- без чужих логотипов, персональных данных и вводящих в заблуждение кадров;
- изображение должно показывать реальную работу плагина;
- автор отвечает за права на изображения.

Если плагин может работать без сети — он должен работать без сети.

## 4. Качество кода

- Код читаемый, без минификации и «умных» однострочников.
- Нет мёртвого кода, тестовых ключей, токенов и локальных путей.
- Нет глобальных переменных, кроме намеренных и понятных.
- Ошибки обрабатываются; падение одной функции не ломает страницу.
- Все таймеры, обработчики и CSS убираются в `onDeactivate`.
- Не более 64 команд и 64 строк панели на плагин.
- Имена команд и строк — короткие и понятные, без эмодзи-спама.
- Настройки имеют `title` и `default`; `description` объясняет эффект.
- Плагин не пишет в консоль секреты и данные пользователя.

Рекомендуется:

- разбить код на функции и файлы (но без динамического импорта);
- добавить `README.md` с примерами и скриншотами;
- проверить работу на пустой ленте, в PiP и после перезагрузки страницы;
- проверить выключение/включение и удаление плагина.

## 5. Сборка и воспроизводимость

Пакет собирается только скриптом:

```bash
node scripts/pack-plugin.js <папка> \
  --out plugins/packages \
  --update-registry plugins/registry.json \
  --key "$OCTO_PLUGIN_SIGNING_KEY"
```

Требования:

- SHA-256 в публикации совпадает с пакетом;
- ZIP детерминирован: одинаковые исходники дают одинаковый хэш;
- в пакете нет файлов, которых нет в исходниках;
- подпись создаётся ключом, публичная часть которого есть в
  `src/main/plugins/plugin-trust.js`;
- приватный ключ не хранится в репозитории, пакете, логах и CI-артефактах;
- при компрометации ключа автор немедленно сообщает в security-контакт, все
  предыдущие подписи отзываются.

## 6. Обновления

- Новая версия не может незаметно расширять разрешения. Если добавляется
  `page:script`, `network` или новый хост, обновление требует подтверждения
  пользователя.
- Нельзя менять смысл плагина под тем же названием.
- Издатель закрепляется при первой установке: ключ подписи, а без подписи —
  `author.name`. Новый ключ, пропавшая подпись или другое имя автора считаются
  сменой издателя: пользователь увидит предупреждение, а новая версия не
  получит настройки, `octo.storage` и `octo.secrets` старой.
- Удаление функции или ухудшение приватности отмечается в changelog.
- Критические исправления безопасности выпускаются отдельной версией и
  сопровождаются описанием.
- Автообновление можно отключить в приложении; плагин не должен этому
  противодействовать.

## 7. Чек-лист ревью

Перед публикацией проверьте:

- [ ] `plugin.json` проходит валидацию приложения.
- [ ] `id` уникален и совпадает с названием репозитория.
- [ ] `version` новая, SemVer, не перезаписывает прошлую.
- [ ] `source` ведёт на тот же код, что в пакете.
- [ ] `LICENSE` на месте, лицензия совместима с правилами.
- [ ] `description` честно описывает функции и сеть.
- [ ] Разрешения минимальны и объяснены.
- [ ] `networkHosts` содержит только необходимые https-хосты.
- [ ] Нет `eval`, `Function`, `require`, `process`, cookie, прямой сети.
- [ ] Нет обфускации, больших base64 и скрытых строк.
- [ ] Все обработчики и CSS убираются при выключении.
- [ ] Плагин не ломает страницу без своих разрешений.
- [ ] Проверены установка, выключение, включение, удаление и обновление.
- [ ] Пакет собран скриптом, SHA-256 и подпись приложены к публикации.
- [ ] Changelog заполнен.
- [ ] Нет секретов, токенов и персональных данных.
- [ ] Для `page:script` есть объяснение, почему без него нельзя.

---

## 8. Отзыв и безопасность

- Автор обязан указать контакт для сообщений об уязвимостях.
- При обнаружении вредоносного поведения плагин удаляется, подпись
  отзывается, пользователи получают уведомление в менеджере.
- Известные уязвимости исправляются в течение 7 дней для критических и 30
  дней для остальных.
- Повторное нарушение после блокировки — постоянный бан.
- Решение по спорным плагинам принимает модератор канала; апелляция — через
  issue в репозитории.

---

## 9. Ответственность

Публикуя плагин, автор подтверждает, что:

- имеет право распространять весь код и ресурсы;
- плагин не нарушает закон и правила TikTok;
- понимает риски `page:script` и сети;
- не будет скрывать изменения от пользователей;
- принимает удаление из канала при нарушении правил.

TikTok Octo не связан с TikTok Ltd. Плагины — независимые работы сообщества;
их авторы не являются представителями проекта.
