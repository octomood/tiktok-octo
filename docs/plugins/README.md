# Плагины TikTok Octo

Плагины — это небольшие JavaScript-пакеты, которые добавляют команды, строки в
панель функций и умеют аккуратно менять страницу TikTok. Они запускаются в
отдельном скрытом окне без Node и системного доступа, а все опасные операции
проходят через проверяемый мост `window.octo`.

Система рассчитана на обычные пользовательские расширения: скрыть блок, добавить
кнопку, посчитать видео, поменять оформление, открыть ссылку. Она не даёт
плагину прочитать файлы, выполнить команду в системе или ходить в сеть мимо
заявленных хостов. Плагин с `page:script` при этом видит всё, что показано на
странице, — подробности в разделе «Ограничения модели».

- Менеджер плагинов: **Плагины → Менеджер плагинов** или
  <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>E</kbd>.
- Плагины публикуются в Telegram-канале
  [t.me/octo_plugins](https://t.me/octo_plugins).
- Установка из скачанного файла `.octoplugin` или `.zip` с проверкой SHA-256 и
  подписей.
- Обновления вручную: новая версия скачивается в канале и ставится файлом.
- Статическая проверка кода до установки.
- Разрешения из манифеста и диалог подтверждения.
- Изоляция: `sandbox: true`, `contextIsolation: true`, без Node, без сети.
- Проверка целостности файлов после установки.

> **Важно.** Плагины — это код сообщества. Даже с песочницей и проверками
> устанавливайте только те плагины, авторам и исходникам которых доверяете.

## SDK, шаблон и hot reload

В репозитории лежит локальный SDK: `plugins/sdk/octo.d.ts` (типы моста),
`plugins/sdk/octo-mock.js` (мок для unit-тестов без Electron) и
`plugins/sdk/template/` (стартовый плагин с командой, строкой панели,
настройкой и хранилищем).

```bash
npm run plugin:new -- my-plugin
OCTO_PLUGIN_DEV_DIR="$PWD/my-plugin" npm start
npm run plugin:dev -- my-plugin   # проверка манифеста при изменениях
```

Запущенное приложение с `OCTO_PLUGIN_DEV_DIR` само перезагружает dev-плагины,
когда меняются файлы в папке: перезапускать вручную не нужно. Подробности и
пример теста — `plugins/sdk/README.md`.

## Быстрый старт

### 1. Возьмите пример

```bash
git clone https://github.com/octomood/tiktok-octo.git
cd tiktok-octo
```

Пример лежит в `plugins/examples/hello-octo/`:

```
hello-octo/
  plugin.json
  index.js
  README.md
```

### 2. Запустите приложение в режиме разработки

```bash
OCTO_PLUGIN_DEV_DIR="$PWD/plugins/examples" npm start
```

Приложение загрузит все папки из `plugins/examples/`, в которых есть
`plugin.json`. Такие плагины:

- не подписаны и не сохраняются в профиль;
- проходят тот же манифест и статическую проверку;
- видны в менеджере с пометкой **«разработка»**;
- не удаляются из интерфейса — вы управляете папкой сами.

После правок нажмите **Настройки → Перезагрузить dev-плагины**.

### 3. Соберите пакет

```bash
node scripts/pack-plugin.js plugins/examples/hello-octo \
  --out plugins/packages \
  --update-registry plugins/registry.json
```

Получится `plugins/packages/app.octo.hello-1.0.0.octoplugin` и запись в
`plugins/registry.json`.

### 4. Установите

**Плагины → Установить из файла…** и выберите `.octoplugin`. Приложение
покажет автора, разрешения, отчёт проверки и подпись. После подтверждения
плагин появится в панели функций и палитре команд.

## Что умеет плагин

| Возможность                   | API                                                | Разрешение    |
| :---------------------------- | :------------------------------------------------- | :------------ |
| Команда в палитре             | `octo.commands.add()`                              | базовое       |
| Строка в панели функций       | `octo.ui.panelRow()` / `updatePanelRow()`          | базовое       |
| Диалоги в интерфейсе          | `octo.ui.confirm()` / `prompt()` / `pick()`        | базовое       |
| Пункт контекстного меню       | `octo.ui.contextMenu.add()`                        | базовое       |
| Горячая клавиша               | `octo.shortcuts.add()`                             | `shortcuts`   |
| Свои настройки                | `manifest.settings` + `octo.settings`              | базовое       |
| Своё хранилище                | `octo.storage` (`keys`, `usage`)                   | базовое       |
| Шифрованные секреты           | `octo.secrets`                                     | базовое       |
| Тема и палитра приложения     | `octo.theme.get()` + `octo.onThemeChange()`        | базовое       |
| Всплывающее сообщение         | `octo.notify()`                                    | базовое       |
| CSS на странице               | `octo.page.injectCSS()` / `setCSS()` / `removeCSS` | `page:css`    |
| Скрипт и наблюдатель страницы | `octo.page.run()` / `getMediaInfo()` / `watch()`   | `page:script` |
| Запросы к своим серверам      | `octo.net.fetch()`                                 | `network`     |
| Переход по страницам TikTok   | `octo.navigate()`                                  | `navigation`  |
| Открыть ссылку в браузере     | `octo.openExternal()`                              | `links`       |
| Управление и события плеера   | `octo.playback` + `onChange()`                     | `playback`    |
| Лента вперёд и назад          | `octo.feed`                                        | `feed`        |
| Загрузка файла TikTok         | `octo.downloads.add()`                             | `downloads`   |
| Плашка на странице            | `octo.ui.overlay`                                  | `overlay`     |
| Язык интерфейса               | `octo.i18n.get()`                                  | `i18n`        |
| Текст в буфер обмена          | `octo.clipboard.write()`                           | `clipboard`   |
| Системное уведомление         | `octo.os.notify()`                                 | `os:notify`   |

Базовые возможности не перечисляются в манифесте: они не трогают страницу и не
ходят в сеть. Всё, что связано со страницей и сетью, пользователь видит в
диалоге установки.

## Структура пакета

Пакет — обычный ZIP с расширением `.octoplugin`. В корне обязателен
`plugin.json`:

```
my-plugin/
  plugin.json      манифест, обязателен
  index.js         точка входа, обязательна
  style.css        любые CSS (по желанию)
  icon.png         иконка для менеджера (по желанию)
  screens/         скриншоты для карточки (до 4, по желанию)
  README.md        описание для людей (рекомендуется)
  LICENSE          лицензия (рекомендуется для публикации)
```

Ограничения:

- пакет — не больше **8 МБ**, распакованный — не больше **24 МБ**;
- не больше **200 файлов**, отдельный файл — до **6 МБ**;
- точка входа — до **2 МБ**;
- только текст и картинки: `.js`, `.json`, `.css`, `.md`, `.txt`, `.png`,
  `.jpg`, `.jpeg`, `.webp`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.otf`, `.ico`,
  а также `LICENSE`, `COPYING` и `NOTICE` без расширения;
- **запрещены** `.html`, `.wasm`, `.node`, `.so`, `.dll`, `.exe`, `.sh`,
  `.py`, `.jar` и любые другие исполняемые форматы;
- символические ссылки, абсолютные пути, `..` и шифрование ZIP запрещены.

Приложение проверяет CRC, имена файлов и размеры. Пакет с опасным путём или
zip-бомбой не будет даже распакован.

## Манифест `plugin.json`

```json
{
  "id": "app.author.my-plugin",
  "name": "Мой плагин",
  "version": "1.2.0",
  "apiVersion": 1,
  "minAppVersion": "0.5.0",
  "description": "Коротко, что делает плагин.",
  "author": {
    "name": "Автор",
    "url": "https://github.com/author"
  },
  "license": "MIT",
  "homepage": "https://github.com/author/my-plugin",
  "source": "https://github.com/author/my-plugin",
  "main": "index.js",
  "icon": "icon.png",
  "screenshots": ["screens/feed.png", "screens/panel.png"],
  "permissions": ["page:css"],
  "settings": [
    {
      "key": "enabled",
      "type": "boolean",
      "title": "Включено",
      "description": "Пояснение для пользователя.",
      "default": true
    }
  ],
  "changelog": "Что изменилось в этой версии."
}
```

### Поля

| Поле            | Обязательно    | Правила                                                                             |
| :-------------- | :------------- | :---------------------------------------------------------------------------------- |
| `id`            | да             | `app.author.plugin`, латиница, цифры, `.` и `-`, до 64 символов, начинается с буквы |
| `name`          | да             | 1–80 символов                                                                       |
| `version`       | да             | SemVer: `1.2.3`, `1.2.3-beta.1`                                                     |
| `apiVersion`    | да             | сейчас только `1`                                                                   |
| `minAppVersion` | нет            | минимальная версия приложения, по умолчанию `0.0.0`                                 |
| `description`   | да             | 1–600 символов                                                                      |
| `author`        | да             | строка или `{ "name": "...", "url": "https://..." }`                                |
| `license`       | рекомендуется  | SPDX-идентификатор, например `MIT`                                                  |
| `homepage`      | нет            | только `https://`                                                                   |
| `source`        | рекомендуется  | ссылка на исходники, только `https://`                                              |
| `main`          | нет            | относительный `.js`, по умолчанию `index.js`                                        |
| `icon`          | нет            | относительный `png/jpg/webp/svg` до 512 КБ                                          |
| `screenshots`   | нет            | до 4 относительных `png/jpg/webp/svg` для карточки                                  |
| `permissions`   | нет            | массив известных разрешений (до 20)                                                 |
| `networkHosts`  | при `network`  | до 30 хостов, можно `*.example.com`                                                 |
| `settings`      | нет            | до 20 настроек                                                                      |
| `cosmetic`      | нет            | `true` — косметический пак: разрешён только `page:css`                              |
| `module`        | нет            | `true` — запускать точку входа как ES-модуль (разрешены только относительные `./`)  |
| `changelog`     | для обновлений | до 4000 символов                                                                    |
| `categories`    | нет            | до 5 коротких тегов                                                                 |

Неизвестное разрешение — ошибка, а не тихое игнорирование. Если в манифесте
нет `page:script`, плагин с вызовом `octo.page.run()` не пройдёт проверку при
установке.

### Настройки

Типы: `boolean`, `string`, `textarea`, `number`, `select`, `color`, `secret`, `action`.
Значения показываются в карточке плагина и сохраняются между запусками. Тип `secret`
шифруется через `safeStorage` и попадает в `octo.secrets.get(key)`, а `action`
рисует кнопку в карточке настроек и вызывает `octo.onSettingAction(fn)`.

```json
{
  "key": "mode",
  "type": "select",
  "title": "Режим",
  "description": "Как вести себя на странице.",
  "options": [
    { "value": "soft", "label": "Мягкий" },
    { "value": "hard", "label": "Строгий" }
  ],
  "default": "soft"
}
```

`key` — `lower_snake_case`, до 48 символов. Значения нормализуются по типу:
неизвестный вариант `select` заменяется на `default`, число обрезается по
`min`/`max`, строка — по `maxLength`.

### Косметические паки

Пакет с `"cosmetic": true` — это набор CSS без скриптов. Манифест разрешает
только `page:css`; `page:script`, `network`, `navigation` и остальные
разрешения с ним отклоняются. Установка, подпись и проверки те же, что у
обычного плагина: пакет ставится из файла, а история версий
позволяет откатиться.

В менеджере пакет помечен «косметика». Если он выключен, рядом появляется
**«Превью»**: пакет включается на 20 секунд, показывает изменения на ленте и
сам выключается. Кнопка включения рядом действует как обычно.

### Квоты и ресурсы

- `octo.storage` — до 256 КБ JSON на плагин.
- Команды — до 64, строки панели — до 64, сочетания клавиш — по правилам
  `shortcuts`.
- `octo.page.run` — изолированный мир, таймаут 10 секунд, результат до 256 КБ.
- `octo.page.injectCSS` — до 256 КБ CSS.
- Пакет — до 8 МБ; точка входа — до 2 МБ; отдельный файл — до 6 МБ.

Карточка плагина в менеджере показывает, сколько занято хранилище и сколько
команд и строк панели зарегистрировано.

## Точка входа и жизненный цикл

`index.js` — классический скрипт (либо ES-модуль с относительными импортами `./...`,
если в манифесте указано `"module": true`). `require()` и внешние пакеты недоступны.
Код выполняется в скрытом окне плагина; страница TikTok в этот момент ещё не
доступна. Регистрируйте команды в `onActivate`, а к странице обращайтесь в
`onPageReady` или по действию пользователя.

```js
let greeting = 'Привет';

octo.onActivate(async () => {
  greeting = octo.settings.get().greeting || greeting;

  await octo.commands.add({
    id: 'hello',
    title: 'Поздороваться',
    description: 'Показывает приветствие.',
    run: () => octo.notify(greeting),
  });

  await octo.ui.panelRow({
    id: 'count',
    label: 'Посчитать видео',
    run: async () => {
      const count = await octo.page.run(`return document.querySelectorAll('video').length;`);
      await octo.notify(`Видео: ${count}`);
    },
  });
});

octo.onSettingsChange((values) => {
  greeting = values.greeting || greeting;
});

octo.onDeactivate(async () => {
  await octo.commands.remove('hello').catch(() => {});
  await octo.ui.removePanelRow('count').catch(() => {});
});
```

### События

| Метод                       | Когда вызывается                                                 |
| :-------------------------- | :--------------------------------------------------------------- |
| `octo.onActivate(fn)`       | плагин запущен, можно регистрировать команды                     |
| `octo.onDeactivate(fn)`     | плагин выключают или приложение закрывается; до 800 мс на уборку |
| `octo.onPageReady(fn)`      | страница TikTok загрузилась; `fn({ url, title })`                |
| `octo.onPageNavigate(fn)`   | SPA-переход внутри TikTok; `fn({ url, title })`                  |
| `octo.onSettingsChange(fn)` | пользователь изменил настройку; `fn(values)`                     |
| `octo.onSettingAction(fn)`  | нажата кнопка настройки с типом `action`; `fn(key)`              |
| `octo.onThemeChange(fn)`    | изменилась тема или палитра приложения; `fn(theme)`              |

Обработчики могут быть асинхронными. Ошибки не роняют приложение: они
попадают в лог плагина и в карточку менеджера.

### Контекст

```js
octo.apiVersion; // 1
octo.plugin; // { id, name, version, author, permissions }
octo.app; // { version, electron, platform }
```

`octo.plugin` и `octo.app` заморожены. Подменить их или получить доступ к
`ipcRenderer` из плагина нельзя.

## API

### `octo.settings.get()`

Возвращает текущие значения настроек синхронно:

```js
const { greeting, accent } = octo.settings.get();
```

Изменять настройки из кода нельзя — это делает пользователь в менеджере.
Слушайте `octo.onSettingsChange`.

### `octo.storage`

Асинхронное хранилище плагина, до 256 КБ на плагин. Значения должны
сериализоваться в JSON.

```js
await octo.storage.set('last-run', Date.now());
const last = await octo.storage.get('last-run');
const keys = await octo.storage.keys();
const usage = await octo.storage.usage(); // { bytes, limit }
await octo.storage.remove('last-run');
await octo.storage.clear();
```

Ключ — `[a-zA-Z0-9._-]`, до 64 символов. Хранилище переживает обновления и
удаляется вместе с плагином.

### `octo.theme.get()`

Возвращает текущую тему и токены палитры Material 3:

```js
const theme = await octo.theme.get();
// { mode: 'dark', dark: true, palette: 'octo-lavender', tokens: { ... } }
```

### `octo.commands.add(spec)`

Добавляет команду в палитру команд и меню «Плагины». Возвращает полный
идентификатор вида `plugin:app.author.plugin:hello`.

```js
await octo.commands.add({
  id: 'hello',            // локальный id, [a-zA-Z0-9._-], до 48
  title: 'Поздороваться', // до 80 символов
  description: '...',     // необязательно
  run(payload) { ... },   // sync или async
});
```

Команда существует, пока плагин активен. При выключении и падении хоста она
исчезает. Не создавайте команды на верхнем уровне файла — используйте
`onActivate`.

### `octo.commands.remove(id)`

Удаляет команду по локальному `id`.

### `octo.ui.panelRow(spec)`

Добавляет строку в категорию **«Плагины»** панели функций:

```js
await octo.ui.panelRow({
  id: 'count',
  label: 'Посчитать видео', // до 80
  description: '...',
  run() { ... },
});
```

Удаление — `octo.ui.removePanelRow(id)`. Обновление на лету —
`octo.ui.updatePanelRow(id, { label, description, badge })`.

### `octo.ui.confirm` / `prompt` / `pick`

Встроенные MD3-диалоги приложения без выхода на страницу:

```js
const ok = await octo.ui.confirm({ title: 'Удалить?', message: 'Очистить список?' });
const name = await octo.ui.prompt({ title: 'Название', placeholder: 'Введите текст…' });
const choice = await octo.ui.pick({
  title: 'Выберите вариант',
  items: [{ value: 'a', label: 'Вариант А', description: 'Пояснение' }],
});
```

### `octo.ui.contextMenu.add(spec)`

Добавляет пункт в контекстное меню страницы:

```js
await octo.ui.contextMenu.add({
  id: 'copy-author',
  title: 'Скопировать автора',
  run(context) {
    // context: { pageURL, linkURL, selectionText, isEditable, mediaType, srcURL }
    octo.notify(context.linkURL || 'нет ссылки');
  },
});
```

Удаление — `octo.ui.contextMenu.remove(id)`. Пункт появляется в меню только
пока плагин активен.

### `octo.shortcuts.add(spec)` — `shortcuts`

Регистрирует внутриприложенческое сочетание клавиш:

```js
await octo.shortcuts.add({
  id: 'random-channel',
  title: 'Случайный канал',
  accelerator: 'Ctrl+Shift+Y',
  run: openRandomChannel,
});
```

Поддерживаются `Ctrl`, `Cmd`/`Meta`, `Alt`, `Shift`, буквы, цифры, F1–F24,
стрелки, Enter, Escape, Space и основные клавиши. Обязателен хотя бы один из
`Ctrl`/`Cmd`/`Alt`, чтобы плагин не перехватывал обычный ввод. Глобальные
системные сочетания недоступны. Если клавиши уже заняты приложением, приоритет
у приложения. Удаление — `octo.shortcuts.remove(id)`.

### `octo.notify(text)`

Короткое сообщение в полосе заголовка. Приложение добавляет имя плагина:
`Мой плагин: текст`. До 300 символов, не чаще 20 раз в минуту.

### `octo.page.injectCSS(css)` — `page:css`

Добавляет CSS на страницу TikTok. `@import` и внешние адреса в `url()`,
`src()` и `image-set()` запрещены, в том числе записанные через
CSS-экранирование (`u\72l(…)`): используйте `data:` URI, если нужна картинка или
шрифт. Относительные адреса (`url(/…)`) и `#фрагменты` разрешены.

```js
await octo.page.injectCSS(`
  [data-e2e="recommend-list-item-container"] {
    outline: 1px solid rgba(255, 179, 193, 0.35);
  }
`);
```

CSS применяется и после перезагрузки страницы, пока плагин включён. Не чаще
30 вызовов в минуту и не больше 512 КБ CSS на плагин. Для обновления или удаления
отдельного блока без накопления правил используйте именованный CSS:

```js
await octo.page.setCSS('frame', 'body { outline: 2px solid #8c84a9; }');
await octo.page.removeCSS('frame');
```

### `octo.page.run(code)` / `getMediaInfo()` / `watch()` — `page:script`

Выполняет строку JavaScript в **изолированном мире** страницы TikTok:

- DOM доступен (`document`, `querySelector`, события, атрибуты, стили);
- внутренние объекты сайта и его JS-переменные — нет;
- Node, `require`, `process` — нет;
- результат должен сериализоваться в JSON (строка, число, массив, объект).

Проверка идёт в два слоя. Сначала статическая: код с явными `fetch`, `eval`,
`document.cookie`, `innerHTML`, навигацией и т. п. отклоняется до запуска с
понятным сообщением. Её можно обойти переименованием (`const f = fetch`), поэтому
настоящая граница — в самом мире, где выполняется скрипт:

- **своя CSP мира** (`default-src 'none'`, без `'unsafe-eval'`): `fetch`,
  `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`, `import()`,
  `new Image()` и шрифты с внешних адресов, а также `eval`, `Function` и
  `[].constructor.constructor` не работают при любом способе вызова. Картинки,
  медиа и шрифты — только `data:` и `blob:`;
- **замки в мире скрипта**: `document.cookie` пуст, `localStorage`,
  `sessionStorage`, `indexedDB`, `cookieStore`, `caches` и `window.open`
  бросают ошибку; нельзя создать `<iframe>`, `<frame>`, `<object>`, `<embed>`,
  `<script>`, `<base>`, `<meta>`, задать атрибуты `on*` или вставить HTML через
  `innerHTML`/`outerHTML`/`insertAdjacentHTML`/`DOMParser` — используйте
  DOM-методы (`createElement`, `append`, `textContent`);
- если защиту мира включить не удалось, скрипт не выполняется вовсе, а вызов
  отклоняется с ошибкой.

Замки ставятся только в мире плагина: сайт и другие плагины их не видят.

```js
const title = await octo.page.run(`return document.title;`);

const videos = await octo.page.run(`
  return [...document.querySelectorAll('video')].map((video) => ({
    width: video.getBoundingClientRect().width,
    paused: video.paused,
  }));
`);
```

Код выполняется как тело функции, поэтому используйте `return`; можно вернуть
Promise, результат дождётся его. Ошибка страницы вернётся как отклонённый
Promise с её текстом. Не чаще 120 вызовов в минуту; результат — до 256 КБ JSON.

Для типовых сценариев доступны безопасные хелперы без ручного парсинга DOM:

```js
const media = await octo.page.getMediaInfo();
// { url, title, author, description, video: { playing, paused, time, duration, width, height } | null }

const stop = await octo.page.watch('comments', '[data-e2e="comment-item"]', (event) => {
  // event: { id, count, matched, texts }
});
await stop(); // или octo.page.unwatch('comments')
```

> **Риск.** `page:script` — самое сильное разрешение. Плагин видит содержимое
> страницы, включая сообщения и элементы интерфейса, и может передать
> прочитанное на хосты из своего `networkHosts` через `octo.net.fetch`. Прямой
> сети у скрипта нет, но DOM общий со страницей: загрузки, которые браузер
> приписывает самой странице (`url()` в стилях элементов, `<audio>`/`<video>`),
> подчиняются CSP сайта, а не CSP мира. Это ограничивает их хостами, которые
> разрешил TikTok, но не запрещает совсем. Поэтому `page:script` — только для
> плагинов, автору которых вы доверяете.

### `octo.playback` — `playback`

Управление текущим роликом.

```js
const status = await octo.playback.status();
// { playing, muted, time, duration, volume, speed }

await octo.playback.playPause();
await octo.playback.seek(12.5);
await octo.playback.setVolume(0.4); // 0…1
await octo.playback.setSpeed(1.5); // 0.5…3
const off = octo.playback.onChange((state) => {
  // { playing, muted, volume, speed, url }
});
```

Громкость и скорость сохраняются как обычные настройки приложения: плагин
меняет их для пользователя, а не только для одного вызова.

### `octo.feed.next()` / `octo.feed.prev()` — `feed`

Перелистывает ленту на следующее или предыдущее видео тем же путём, что и
кнопки приложения. Работает и в PiP.

### `octo.downloads.add(url)` — `downloads`

Запускает загрузку файла по ссылке TikTok или его CDN. Разрешены только
`https://tiktok.com`, `https://*.tiktok.com` и `https://*.tiktokcdn*.com`;
остальные адреса отклоняются. Имя файла и папка подчиняются настройкам
«Загрузок» приложения.

### `octo.ui.overlay.show(spec)` / `hide(id)` — `overlay`

Короткая текстовая плашка поверх страницы.

```js
const { id } = await octo.ui.overlay.show({ text: 'Готово', timeoutMs: 2500 });
await octo.ui.overlay.hide(id);
```

HTML, картинки и чужие элементы не вставляются: только текст (до 200 символов),
который исчезает сам через `timeoutMs` (500–15000).

### `octo.i18n.get()` — `i18n`

```js
const { locale, dir } = await octo.i18n.get(); // { locale: 'ru', dir: 'ltr' }
```

Язык интерфейса приложения и направление текста. Переводы своих строк плагин
хранит сам.

### `octo.clipboard.write(text)` — `clipboard`

Копирует текст (до 10 000 символов) в буфер обмена. Читать буфер и подменять
его без вызова плагина нельзя.

### `octo.os.notify({ title, body })` — `os:notify`

Показывает системное уведомление от имени TikTok Octo. Заголовок до 80
символов, текст до 300; не больше 10 уведомлений в минуту. Чужие уведомления
плагин не читает. Если система не поддерживает уведомления, текст показывается
обычной плашкой приложения.

```js
await octo.os.notify({ title: 'Сохранено', body: 'Видео добавлено в очередь' });
```

### `octo.net.fetch(url, options)` — `network`

Запрос к вашему серверу. Только `https://` (и `http://localhost` для
разработки), только хосты из `networkHosts`, без cookies приложения и сессии
TikTok.

```js
const response = await octo.net.fetch('https://api.example.com/v1/ping', {
  method: 'GET',
  headers: { Accept: 'application/json' },
});
// { ok, status, url, headers, text }
```

Ограничения: методы `GET/POST/PUT/PATCH/DELETE`, тело до 100 КБ, ответ до
2 МБ, таймаут 15 с, 30 запросов в минуту, редирект на другой хост запрещён.
Заголовки `Cookie`, `Host`, `Origin`, `Referer`, `Content-Length` отбрасываются.
Это не замена `fetch` со страницы: cookies TikTok сюда не попадают.

### `octo.navigate(url)` — `navigation`

Открывает страницу TikTok внутри приложения:

```js
await octo.navigate('/@username');
await octo.navigate('https://www.tiktok.com/search?q=octo');
```

Принимаются только относительные пути и `https://…tiktok.com`. Внешние сайты,
`javascript:` и произвольные схемы запрещены. Для навигации по клику на DOM
это удобнее, чем создавать ссылку вручную.

### `octo.secrets`

Шифрованное хранилище строк для токенов и паролей. Использует системное
хранилище ключей Electron (`safeStorage`), а не обычный JSON.

```js
await octo.secrets.set('api-token', '...');
const token = await octo.secrets.get('api-token');
await octo.secrets.remove('api-token');
await octo.secrets.clear();
```

До 64 КБ на значение и 128 КБ на плагин. Если системное хранилище недоступно,
вызов вернёт ошибку — в этом случае не сохраняйте секреты в `octo.storage`.

### `octo.openExternal(url)` — `links`

Открывает `https://`-ссылку в системном браузере. Другие схемы запрещены.

### `octo.log(...args)`

Пишет в консоль main-процесса при `OCTO_DEBUG=1` и в **логи плагина**. Логи
видны в карточке «Установленные» → «Разрешения, проверка, логи и настройки»,
их можно обновить кнопкой «Обновить». Не пишите туда токены и персональные
данные.

## Разрешения

Базовые возможности (`ui`, `storage`, `notify`) доступны всем. Остальные
перечисляются в `permissions` и показываются в диалоге установки:

| Разрешение    | Риск    | Что даёт                                                   |
| :------------ | :------ | :--------------------------------------------------------- |
| `page:css`    | средний | добавлять, обновлять и удалять CSS на странице             |
| `page:script` | высокий | DOM, `getMediaInfo`, `watch` и скрипт в изолированном мире |
| `network`     | высокий | запросы только на хосты из `networkHosts`                  |
| `navigation`  | средний | открывать страницы tiktok.com в приложении                 |
| `shortcuts`   | средний | назначать горячие клавиши                                  |
| `links`       | низкий  | открывать https-ссылки в браузере                          |
| `playback`    | средний | управлять плеером и подписываться на его состояние         |
| `feed`        | средний | перелистывать ленту вперёд и назад                         |
| `downloads`   | высокий | запускать загрузку по ссылке TikTok или его CDN            |
| `overlay`     | низкий  | показывать короткую текстовую плашку поверх страницы       |
| `i18n`        | низкий  | узнавать язык интерфейса и направление текста              |
| `clipboard`   | низкий  | копировать текст в буфер обмена                            |
| `os:notify`   | низкий  | показывать системные уведомления от имени приложения       |

Принцип минимальных прав: если плагин может работать без `page:script`, не
просите его. Проверка при установке отклоняет манифест, где заявлено меньше
прав, чем использует код.

## Безопасность

### Что делает приложение

1. **Манифест.** Строгая схема, известные разрешения, безопасные пути.
2. **ZIP.** CRC, лимиты, запрет symlink/path traversal/ZIP64/шифрования.
3. **Статический аудит.** AST-разбор JavaScript плюс текстовые правила:
   блокируются `require`, `process`, `eval`, `Function`, прямые
   `fetch`/XHR/WebSocket, cookie, навигация, `document.write`, `innerHTML`,
   Worker, WebAssembly, нативные файлы, майнинг, обфускация и т.п. Если код не
   разбирается парсером, установка блокируется.
4. **Проверка соответствия.** Код не может использовать `octo.page.run`,
   `octo.page.injectCSS`, `octo.net.fetch`, `octo.navigate`,
   `octo.shortcuts.add` или `octo.openExternal` без соответствующего разрешения.
5. **Диалог.** Пользователь видит автора, версию, источник, подпись,
   разрешения, предупреждения и итог проверки.
6. **Подпись.** SHA-256 пакета + Ed25519-подпись издателя (как встроенный
   `SIGNATURE.json` внутри `.octoplugin` для установки из файла, так и подпись
   в `registry.json`). Недействительная подпись блокирует установку; неподписанные
   плагины регулируются настройкой.
7. **Песочница.** Отдельное скрытое окно, `sandbox: true`,
   `contextIsolation: true`, без Node, без preload сайта, эфемерная сессия.
   Скрипты на странице (`page:script`) идут в отдельный изолированный мир со
   своей строгой CSP и замками на cookie, хранилища, фреймы и вставку HTML
   (см. `octo.page.run`).
8. **Сеть.** На уровне сессии плагина все `http/https/ws/wss` отменяются.
   Сетевые запросы — только через `octo.net.fetch` с allowlist.
9. **Секреты.** `octo.secrets` шифрует значения через системное хранилище
   ключей; обычное `octo.storage` остаётся простым JSON.
10. **Целостность.** После установки считаются хэши файлов; если файл изменили
    вручную, плагин помечается «изменён» и не запускается.
11. **Падения.** После трёх падений подряд плагин автоматически отключается,
    чтобы не устраивать цикл перезапусков.
12. **Обновления.** Установка новой версии с новыми разрешениями или
    изменёнными сетевыми хостами не проходит молча — она ждёт подтверждения.

### Что плагин не может

- читать файлы, запускать процессы, ставить пакеты;
- получить `require`, `process`, `ipcRenderer`, `shell`;
- открыть своё окно, iframe, `<script>` или уйти на другой URL;
- ходить в сеть напрямую — ни из окна плагина, ни из скрипта на странице;
- остаться работать после выключения или удаления.

### Ограничения модели

Плагин с `page:script` живёт в одном DOM со страницей. Он может читать
видимый текст и элементы интерфейса. Это осознанный компромисс: без доступа к
DOM большинство полезных расширений невозможны. Что из этого следует:

- всё прочитанное плагин может отправить на хосты из своего `networkHosts`;
- CSP мира закрывает сетевые API и `eval` скрипта, но не загрузки, которые
  браузер приписывает самой странице: `url()` в стилях элементов,
  `<audio>`/`<video>`, переход уже существующих фреймов страницы. Для них
  действует CSP сайта — только хосты, которые разрешил TikTok;
- переход страницы на внешний адрес не остаётся в приложении: такой адрес
  открывается в системном браузере, и пользователь это видит;
- замки на cookie и хранилища — защита от небрежного и очевидного кода, а не
  граница: через уже существующие фреймы страницы их можно обойти.

Поэтому:

- ставьте `page:script` только доверенным плагинам;
- перед публикацией требуйте исходники и проверяйте их;
- для чувствительных сценариев используйте строгий режим «только подписанные».

## Сборка, подпись и публикация

Пакеты публикуются в Telegram-канале [t.me/octo_plugins](https://t.me/octo_plugins).
Встроенного каталога в менеджере больше нет: пользователь скачивает
`.octoplugin` из канала и устанавливает файлом. `registry.json` и
`--update-registry` остаются для сборки и совместимости, но приложение их не
запрашивает.

### Упаковка

```bash
node scripts/pack-plugin.js <папка> \
  --out plugins/packages \
  [--base-url https://raw.githubusercontent.com/.../plugins/packages] \
  [--update-registry plugins/registry.json] \
  [--key .octo-keys/plugin-private.pem]
```

Скрипт:

- проверяет манифест и запускает тот же статический аудит;
- отказывается собирать пакет с блокирующими находками;
- делает детерминированный ZIP (фиксированная дата и порядок файлов);
- считает SHA-256 и, если задан ключ, подпись Ed25519;
- печатает готовую запись для `registry.json`.

### Ключи

```bash
node scripts/plugin-keygen.js
```

Ключи появятся в `.octo-keys/` (папка в `.gitignore`). Публичный ключ
вставьте в `src/main/plugins/plugin-trust.js`:

```js
const PUBLIC_KEYS = ['-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----'];
```

Приватный ключ храните только в CI (переменная `OCTO_PLUGIN_SIGNING_KEY` —
путь к PEM). В репозиторий его нельзя.

Подписывается каноническая строка:

```
octo-plugin-v1
<id>
<version>
<sha256>
```

### `registry.json`

Формат `registry.json` по-прежнему создаётся `--update-registry` для архивов и
старых сборок, но менеджер его не загружает и не показывает. Не добавляйте в
него приватные данные: для пользователей источником плагинов остаётся канал
[t.me/octo_plugins](https://t.me/octo_plugins).

## Обновления вручную

Автообновлений по каталогу больше нет. Новая версия скачивается в
Telegram-канале и ставится файлом через «Установить из файла». При установке
проверяются SHA-256, подпись, манифест и код; если версия добавляет разрешения
или меняет `networkHosts`, приложение попросит подтверждение. Настройки,
обычное хранилище и секреты сохраняются.

### История версий и откат

При обновлении приложение сохраняет до трёх предыдущих версий. В карточке
«Установленные» → «История версий» можно откатить плагин на любую из них.
Настройки, обычное хранилище и секреты при откате сохраняются. Резервные копии
удаляются вместе с плагином.

## Ограничения

- Только JavaScript. Нативные модули, WASM и фоновые Worker запрещены.
- Нет `fetch` из плагина: сеть — только через `octo.net.fetch` и allowlist.
- Нет прямого доступа к API TikTok и приватным запросам. Плагин работает с тем
  же DOM, что и пользователь.
- `page.run` выполняется в изолированном мире со своей CSP: глобальные объекты
  сайта и прямая сеть недоступны, но DOM общий.
- Плагины не могут добавлять свои окна и вкладки.
- Настройки плагина меняет пользователь, а не код.
- Приложение не гарантирует работу сторонних плагинов после обновлений
  TikTok: селекторы и структура страницы могут меняться.

## Документация в приложении

Документация собирается из `README.md` и `PUBLISHING.md` и входит в сборку:

```bash
node scripts/build-plugin-docs.js
# результат: src/renderer/plugins-docs/
```

Меню «Плагины», панель функций и менеджер открывают её в отдельном локальном
окне — без сети, внешних сервисов и публикации. Внутренние ссылки работают,
внешние уходят в системный браузер.

При необходимости тот же генератор умеет собрать статический сайт для любого
хостинга:

```bash
node scripts/build-plugin-docs.js --out docs/plugins/site
```

## FAQ

**Плагин не появился в панели.**
Проверьте «Установленные»: возможно, он выключен, упал или помечен «изменён».
Включите и посмотрите `lastError`.

**Почему `fetch` не работает?**
Прямая сеть запрещена. Добавьте разрешение `network`, перечислите хосты в
`networkHosts` и используйте `octo.net.fetch`.

**Почему `octo.page.run` отклонён?**
Нет разрешения `page:script` или в коде есть `fetch`, `eval`, `document.cookie`,
навигация и другие запрещённые конструкции. Если код прошёл проверку, но упал с
«недоступно скриптам плагинов» или нарушением Content Security Policy, — он
упёрся в защиту мира: сеть — через `octo.net.fetch`, HTML — через DOM-методы.

**Можно ли поставить неподписанный плагин?**
Да, если в настройках разрешены неподписанные. В строгом режиме — нет.
Недействительная подпись блокируется всегда.

**Где хранятся плагины?**
В профиле приложения: `plugins/<id>/`, состояние — `plugins-state.json`.
Точный путь показан в настройках менеджера.

**Как удалить всё?**
Удалите плагин в менеджере или папку `plugins` в профиле приложения.
