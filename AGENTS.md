# Правила для агентов

Этот файл обязателен для AI-агентов и контрибьюторов, которые меняют
репозиторий. Если правило конфликтует с прямой просьбой пользователя, сначала
уточните конфликт, а не молча выбирайте одну сторону.

## 1. Changelog — часть definition of done

Любое изменение, которое видит пользователь, должно попасть в `CHANGELOG.md`
**в том же изменении, а не отдельным коммитом потом**.

- Следуйте структуре, которая уже есть в `CHANGELOG.md`: правка идёт в раздел
  текущей версии из `package.json`, а если после версионного раздела уже
  заведён `## Не выпущено` — в него.
- Секции: `### Добавлено`, `### Изменено`, `### Исправлено`, `### Удалено`.
- Формулировки — по-русски, кратко и в терминах пользовательского эффекта:
  что изменилось и зачем. Внутренние подробности — только если они помогают
  понять изменение.
- Указывайте затронутые разрешения, настройки, файлы или тесты, когда это
  важно для проверки.
- Не переписывайте и не удаляйте чужие записи без необходимости. Дополняйте
  существующие пункты, если изменение логически продолжает их.
- Не создавайте новый раздел версии и не меняйте версию в `package.json` без
  явной просьбы.
- Задача без записи в changelog считается незавершённой.

Шаблон:

```md
- **Короткое название** — что изменилось для пользователя. Если нужно:
  где это видно, какое разрешение/настройка задействованы, какой тест
  покрывает.
```

## 2. Документация

- Пользовательское поведение, UX, настройки и ограничения — обновляйте
  `README.ru.md` и `README.md` (английское зеркало).
- API плагинов, разрешения и правила публикации — `docs/plugins/` и
  `docs/plugins/PUBLISHING.md`; после правок запускайте `npm run docs:build`.
- Не обещайте в документации то, чего нет в коде, и явно фиксируйте
  ограничения (например, что стикер уходит как обычное фото).

## 3. Тесты и проверки

- Новая функциональность и исправления поведения — добавляйте или обновляйте
  Playwright-тест в `test/`.
- Если тест объективно невозможен (например, нативный диалог), объясните это в
  ответе и покройте ближайшую доступную часть.
- Перед завершением запускайте:

```bash
npm run lint
npm test
npx prettier --check <изменённые файлы>
```

- Форматирование всего репозитория может затронуть чужие незакоммиченные
  файлы. Проверяйте формат точечно по своим файлам.

## 4. Архитектура и безопасность

- Не добавляйте приватные API TikTok, обход подписей, scraping cookies и
  прочие способы обойти защиту сайта.
- Плагины остаются в песочнице: без Node, файловой системы и прямой сети;
  доступ только через `window.octo` и разрешения из манифеста.
- Не логируйте токены, cookies, содержимое чатов и другие приватные данные.
- Не ослабляйте CSP, `contextIsolation`, `sandbox` и проверки навигации без
  явной необходимости и объяснения в changelog.
- Сохраняйте чужие незакоммиченные изменения: правьте точечно, не переписывайте
  файлы целиком без причины.

## 5. Стиль кода

- Main-процесс: CommonJS, `'use strict'`, 2 пробела, одинарные кавычки,
  висячие запятые, ширина 100.
- Renderer: классический скрипт без Node, только `window.octo` и DOM.
- Пользовательские строки интерфейса — по-русски; английский README — зеркало
  русского, а не отдельный продукт.
- Следуйте структуре и именованию соседних модулей.

## 6. Чек-лист перед завершением

- [ ] `CHANGELOG.md` обновлён в текущем разделе.
- [ ] `README.ru.md` / `README.md` и `docs/` обновлены, если изменилось
      поведение или API.
- [ ] Добавлены или обновлены тесты.
- [ ] `npm run lint` проходит.
- [ ] `npm test` проходит.
- [ ] Изменённые файлы проходят `prettier --check`.
